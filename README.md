# לוח שליטה טקטי - חפ"ק

תמונה מבצעית משותפת לכמה עמדות: לו"ז ושעוני יעד, אירועים, כוחות, גורמי חוץ ויומן מבצעים. כל העמדות רואות ועורכות את אותם נתונים בזמן אמת.

> כל הנתונים בפרויקט הם נתוני הדגמה בדויים.

## איך זה בנוי

```
 עמדה (דפדפן) ─┐
 עמדה (דפדפן) ─┼─ WebSocket ─→ שרת Node ─→ SQLite (קובץ אחד)
 עמדה (דפדפן) ─┘
```

- **השרת הוא מקור האמת.** עמדה שולחת פעולה, למשל "פתיחת אירוע". השרת בודק אותה, מקצה מספר, רושם ביומן עם שם העמדה ושעת השרת, ומפיץ את השינוי לכל העמדות.
- **עריכה בו-זמנית:** נשלחים רק השדות שהעמדה שינתה בפועל. אם שתי עמדות עורכות שדות שונים באותה רשומה, שני השינויים נשמרים.
- **ניתוק:** מוצג פס אדום והעריכה נחסמת עד שהחיבור חוזר, כדי שאף אחד לא יערוך על סמך נתונים ישנים. אחרי החיבור מחדש העמדה מקבלת את המצב העדכני.
- **התראות:** אירוע בדרג 1, שינוי רמת כוננות או תרגיל שמתבצעים בעמדה אחת מקפיצים התראה קולית וחזותית בכל שאר העמדות.
- **מה נשמר רק בעמדה:** המסך הנוכחי ומצב השמע נשמרים בדפדפן של העמדה. כל השאר נשמר בשרת.

## הרצה לפיתוח

```bash
npm install
npm run dev      # מפעיל את השרת (פורט 8787) ואת Vite (פורט 5173) יחד
```

פותחים את http://localhost:5173. קוד הגישה בפיתוח הוא `1234`.

## הפעלה ברשת החפ"ק (HTTPS)

על המחשב שישמש כשרת (צריך Node 22 ומעלה):

```bash
npm ci
npm run build
npm run cert                        # פעם אחת: רשות אישורים פנימית ותעודה לשרת
ACCESS_CODE='<קוד חזק>' npm start   # HTTPS בפורט 8443
```

`npm run cert` יוצר בתיקייה `data/tls/` רשות אישורים פנימית (CA) לחפ"ק, ותעודה לשרת. התעודה מכסה את כל הכתובות שדרכן אפשר להגיע לשרת: שם המחשב, `<שם>.local` וכל כתובות ה-IP של כרטיסי הרשת. כדי להוסיף שם או כתובת: `npm run cert -- hq.local 10.0.0.5`.

כשהקבצים קיימים, `npm start` עולה ב-HTTPS אוטומטית:
- **`https://<כתובת-השרת>:8443`**: המערכת עצמה. גם החיבור החי (WebSocket) מוצפן.
- **`http://<כתובת-השרת>:8080`**: עמוד עזר לא מוצפן. הוא מפנה ל-HTTPS ומאפשר להוריד את תעודת ה-CA. אפשר לכבות אותו עם `HTTP_PORT=0`.

### התקנת התעודה בכל עמדה (פעם אחת)

מורידים את `http://<כתובת-השרת>:8080/ca.crt` ומתקינים אותה כ**רשות אישורים מהימנה**. לפני ההתקנה הדפדפן יציג אזהרה. אחריה החיבור מאובטח ובלי אזהרות.

| מכשיר | התקנה |
|---|---|
| **Windows** | לחיצה כפולה על הקובץ ← "התקן אישור" ← "מחשב מקומי" ← "הצב את כל האישורים במאגר הבא" ← **רשויות אישורים עליונות מהימנות**. לסגור את הדפדפן ולפתוח מחדש |
| **macOS** | לחיצה כפולה (נפתח ב-Keychain Access) ← לחיצה כפולה על התעודה ← Trust ← When using this certificate: **Always Trust** |
| **Android** | הגדרות ← אבטחה ← הצפנה ואישורים ← התקנת אישור ← **אישור CA** ← בחירת הקובץ |
| **iPhone/iPad** | פותחים את הקישור ב-Safari ומאשרים את הורדת הפרופיל ← הגדרות ← "הפרופיל הורד" ← התקנה. אחר כך: הגדרות ← כללי ← אודות ← הגדרות אמון באישורים ← להפעיל את האישור |
| **Linux (Chrome)** | הגדרות ← פרטיות ואבטחה ← אבטחה ← ניהול אישורים ← Authorities ← Import ← לסמן "Trust this certificate for identifying websites" |
| **Firefox (כל מערכת)** | Firefox משתמש במאגר משלו: הגדרות ← פרטיות ואבטחה ← אישורים ← הצגת אישורים ← Authorities ← Import ← לסמן אמון לאתרים |

### תחזוקת התעודות

- **כתובת IP או שם של השרת השתנו:** מריצים שוב `npm run cert` ומפעילים את השרת מחדש. ה-CA נשמר, כך שעמדות שכבר התקינו אותו לא צריכות לעשות כלום.
- **תוקף:** תעודת השרת תקפה 825 ימים (המקסימום שמכשירי Apple מקבלים), ו-CA תקף 10 שנים. לחדש עם `npm run cert` לפני שהתוקף פג. הפקודה מדפיסה את התאריך.
- **`data/tls/ca.key` הוא הקובץ הרגיש ביותר במערכת.** מי שמחזיק בו יכול להתחזות לשרת בפני כל העמדות. יש לשמור עליו ועל הגיבויים שלו בהגבלת גישה. הסקריפט יוצר את קבצי המפתח עם הרשאה לבעלים בלבד.
- **תעודה ממקור אחר:** אפשר להגדיר `TLS_CERT` ו-`TLS_KEY` לקבצים של תעודה שהונפקה אחרת.

### הגדרות (משתני סביבה)

| משתנה | ברירת מחדל | הסבר |
|---|---|---|
| `ACCESS_CODE` | — (חובה בהפעלה) | הקוד המשותף שהעמדות נכנסות איתו |
| `PORT` | `8443` עם HTTPS, `8787` בלי | הפורט של המערכת |
| `HTTP_PORT` | `8080` | עמוד העזר (הפניה ל-HTTPS והורדת ה-CA). `0` מכבה אותו. קיים רק כש-HTTPS פעיל |
| `TLS_CERT` / `TLS_KEY` / `TLS_CA` | `data/tls/server.crt` / `server.key` / `ca.crt` | קבצי התעודה |
| `HOST` | `0.0.0.0` | ממשק הרשת. `127.0.0.1` מגביל לגישה מאותו מחשב בלבד |
| `DB_PATH` | `data/tactical.db` | מיקום קובץ הנתונים |
| `SESSION_SECRET` | נוצר ונשמר בקובץ הנתונים | מפתח החתימה של הכניסות. החלפתו מנתקת את כל העמדות |
| `TRUST_PROXY` | `0` (כבוי) | מספר ה-reverse proxies שלפני השרת. רלוונטי רק אם בכל זאת מציבים proxy (ראו "אבטחה") |

כניסה של עמדה תקפה 12 שעות, כלומר משמרת אחת. אחרי 5 ניסיונות כניסה שגויים מאותה כתובת, הכתובת נחסמת לדקה.

### גיבוי

כל הנתונים נמצאים בקובץ `DB_PATH`, כולל היומן המלא. העמדות רואות רק את 500 הרשומות האחרונות, והשרת שומר את כולן.

- **הדרך הפשוטה:** לעצור את השרת, להעתיק את תיקיית `data/`, ולהפעיל את השרת מחדש.
- **גיבוי בלי עצירה:** `sqlite3 data/tactical.db ".backup backup.db"`.

## אבטחה - חשוב לפני שימוש אמיתי

1. **HTTPS.** בלי `npm run cert` השרת עולה ב-HTTP ומזהיר בלוג, כי אז קוד הגישה והנתונים עוברים ברשת בלי הצפנה. אם בוחרים בכל זאת להציב reverse proxy עם תעודה משלו (Caddy או nginx), צריך להגדיר `TRUST_PROXY` למספר ה-proxies. בלי ההגדרה, כל העמדות מגיעות מכתובת ה-proxy, וכמה ניסיונות שגויים יחסמו את כולן. השרת סומך רק על הכתובות שה-proxies עצמם הוסיפו, ולכן לקוח לא יכול לזייף כתובת כדי לעקוף את החסימה.
2. **קוד גישה משותף** מתאים לצוות קטן ומוכר, אבל הוא לא מזהה אנשים. שם העמדה מוקלד בכניסה ואינו מאומת. אם נדרשת אחריותיות אישית, השלב הבא הוא משתמשים אישיים עם הרשאות.
3. **קובץ הנתונים ותיקיית `data/tls`** מכילים את כל המידע המבצעי ואת מפתחות ההצפנה. יש להגביל גישה לתיקייה ולגיבויים.
4. **קוד גישה חזק.** קוד קצר, כמו 4 ספרות, אפשר לנחש גם עם החסימה. ברשת אמיתית כדאי להשתמש בקוד של 12 תווים ומעלה.
