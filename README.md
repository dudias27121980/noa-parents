# לוח שליטה טקטי - חפ"ק

תמונה מבצעית משותפת לכמה עמדות: לו"ז ושעוני יעד, אירועים, כוחות, גורמי חוץ ויומן מבצעים. כל העמדות רואות ועורכות את אותם נתונים בזמן אמת.

> כל הנתונים בפרויקט הם נתוני הדגמה בדויים.

## איך זה בנוי

```
 עמדה (דפדפן) ─┐
 עמדה (דפדפן) ─┼─ WebSocket ─→ שרת Node ─→ SQLite (קובץ אחד)
 עמדה (דפדפן) ─┘
```

- **השרת הוא מקור האמת.** עמדה שולחת פעולה, למשל "פתיחת אירוע". השרת בודק אותה, מקצה מספר, רושם ביומן עם שם העמדה ושעת השרת, ומפיץ את השינוי לכל העמדות.
- **עריכה בו-זמנית:** נשלחים רק השדות שהעמדה שינתה בפועל. אם שתי עמדות עורכות שדות שונים באותה רשומה, שני השינויים נשמרים.
- **ניתוק:** מוצג פס אדום והעריכה נחסמת עד שהחיבור חוזר, כדי שאף אחד לא יערוך על סמך נתונים ישנים. אחרי החיבור מחדש העמדה מקבלת את המצב העדכני.
- **התראות:** אירוע בדרג 1, שינוי רמת כוננות או תרגיל שמתבצעים בעמדה אחת מקפיצים התראה קולית וחזותית בכל שאר העמדות.
- **מה נשמר רק בעמדה:** המסך הנוכחי ומצב השמע נשמרים בדפדפן של העמדה. כל השאר נשמר בשרת.

## הרצה לפיתוח

```bash
npm install
npm run dev      # מפעיל את השרת (פורט 8787) ואת Vite (פורט 5173) יחד
```

פותחים את http://localhost:5173. קוד הגישה בפיתוח הוא `1234`.

## הפעלה ברשת החפ"ק

על המחשב שישמש כשרת (צריך Node 22 ומעלה):

```bash
npm ci
npm run build
ACCESS_CODE='<קוד חזק>' npm start
```

העמדות גולשות לכתובת `http://<כתובת-השרת>:8787`. בכניסה כל עמדה מזינה שם עמדה ואת קוד הגישה.

### הגדרות (משתני סביבה)

| משתנה | ברירת מחדל | הסבר |
|---|---|---|
| `ACCESS_CODE` | — (חובה בהפעלה) | הקוד המשותף שהעמדות נכנסות איתו |
| `PORT` | `8787` | הפורט שהשרת מאזין עליו |
| `HOST` | `0.0.0.0` | ממשק הרשת. הערך `127.0.0.1` מגביל לגישה מאותו מחשב בלבד |
| `DB_PATH` | `data/tactical.db` | מיקום קובץ הנתונים |
| `SESSION_SECRET` | נוצר ונשמר בקובץ הנתונים | מפתח החתימה של הכניסות. החלפתו מנתקת את כל העמדות |
| `TRUST_PROXY` | `0` (כבוי) | מספר ה-reverse proxies שלפני השרת, בדרך כלל `1`. להגדיר רק מאחורי proxy בשליטתכם (ראו בהמשך) |

כניסה של עמדה תקפה 12 שעות, כלומר משמרת אחת. אחרי 5 ניסיונות כניסה שגויים מאותה כתובת, הכתובת נחסמת לדקה.

### גיבוי

כל הנתונים נמצאים בקובץ `DB_PATH`, כולל היומן המלא. העמדות רואות רק את 500 הרשומות האחרונות, והשרת שומר את כולן.

- **הדרך הפשוטה:** לעצור את השרת, להעתיק את תיקיית `data/`, ולהפעיל את השרת מחדש.
- **גיבוי בלי עצירה:** `sqlite3 data/tactical.db ".backup backup.db"`.

## אבטחה - חשוב לפני שימוש אמיתי

1. **HTTPS.** השרת עצמו מדבר HTTP, ולכן קוד הגישה ותוכן הנתונים עוברים ברשת בלי הצפנה. ברשת שאינה סגורה לחלוטין, יש להציב לפני השרת reverse proxy עם תעודה, למשל Caddy או nginx. אחרי שעושים את זה צריך להגדיר `TRUST_PROXY=1`, או את מספר ה-proxies אם יש יותר מאחד. בלי ההגדרה, כל העמדות מגיעות מכתובת ה-proxy, וכמה ניסיונות שגויים יחסמו את כולן. השרת סומך רק על הכתובות שה-proxies עצמם הוסיפו, ולכן לקוח לא יכול לזייף כתובת כדי לעקוף את החסימה.
2. **קוד גישה משותף** מתאים לצוות קטן ומוכר, אבל הוא לא מזהה אנשים. שם העמדה מוקלד בכניסה ואינו מאומת. אם נדרשת אחריותיות אישית, השלב הבא הוא משתמשים אישיים עם הרשאות.
3. **קובץ הנתונים** מכיל את כל המידע המבצעי. יש להגביל גישה לתיקייה ולגיבויים.

## בדיקות

```bash

```

- בדיקות הממשק מריצות את לוגיקת השרת האמיתית בזיכרון, ומחברות אליה עמדה אחת או יותר.
- בדיקות השרת מריצות שרת אמיתי ברשת: כניסה, חסימה, WebSocket, קבצים סטטיים ואתחול.

ה-CI ב-GitHub Actions מריץ בדיקת טיפוסים, בדיקות ובנייה על כל PR.
